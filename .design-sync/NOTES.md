# design-sync notes — EssayRead Design System

Project: `EssayRead Design System` (claude.ai/design) · projectId `cf896ca6-97d2-424d-b8ad-048c8efa2785`
Shape: **package** (no Storybook). This repo is the Easy Essay **application**, not a component library.

## How the bundle is produced (non-obvious)

- There is **no library `dist/` entry**. `frontend/dist/` is a Vite *app* build. We bundle a hand-written
  **scoped barrel**, `frontend/ds-entry.tsx`, via `--entry` (synth-entry mode is bypassed). esbuild externalizes
  react/react-dom to `window.React`/`window.ReactDOM`, so the bundle is ~33 KB with **zero app deps inlined**.
- `cfg.entry` = `./frontend/ds-entry.tsx`; `cfg.pkg` = `essay-read-frontend`; `cfg.globalName` = `EssayReadDS`.
- **`cfg.cssEntry` (`frontend/ds-styles.css`) is GENERATED and gitignored.** It is `cfg.buildCmd`
  (`bash .design-sync/build-css.sh`): compiles `frontend/src/styles/globals.css` with the app's Tailwind config
  (scoped to the curated components) and prepends `.design-sync/tokens-root.css`. **Re-run buildCmd before the
  converter on every re-sync / fresh clone.**
- **No provider is configured** — none of the curated components read React context (only `useState`/`useEffect`/etc.).

## Scope (curated subset, by user decision)

In (10 components): `SkeletonLine/Block/Circle/Card/Analysis`, `Tooltip`, `ConfirmDialog`, `LoadingSpinner`,
`LoadingState`, `ShortcutHelp`. All are clean, presentational, CSS-var driven.

Deliberately **excluded** (app-coupled — do not add without reworking): `Layout`, `Sidebar`, `ThemeProvider`
(needs `useUIConfig`), `SelectionPopup` (router + textAction API + PDF), `TerminalPanel` (xterm), `VersionPopup`
(app changelog), `ErrorBoundary`/`PageErrorBoundary`, `ShortcutHelp`'s siblings, and all 8 pages / feature modules.

## .d.ts contracts

No build emits `.d.ts`, so all 10 prop contracts are hand-written in `cfg.dtsPropsFor` (mirrors the inline
`interface`s in each component's source). `LoadingState.partialResult` is typed loosely as `Record<string, unknown>`
(real app type is `Partial<AnalysisResult>`). **If a component's props change in source, update `cfg.dtsPropsFor`.**

Validate's `.d.ts` parse check prints *"skipped — typescript not in node_modules"* even when typescript IS installed:
under Node 22, `await import('typescript')` doesn't synthesize named exports (`ts.createSourceFile` is undefined →
silent catch). Harmless converter quirk. The 10 `.d.ts` files were parse-checked manually (0 errors).

## Known render warns (checked, benign)

- **Tooltip** bubble is hover/focus-only (portals to `<body>`), so static cards show the **triggers**, not the open
  bubble. Both trigger compositions render correctly. This is the honest best static render.
- `--tw-shadow-color` reported as 1 missing token (below threshold) — a Tailwind internal, harmless.
- `ConfirmDialog` / `ShortcutHelp` are `position: fixed` overlays; their previews wrap them in a `transform: translateZ(0)`
  box so the fixed backdrop is contained and the open dialog centers in a sized card. (Without the wrapper they trip
  `[RENDER_THIN]` 0px height and clip at the top.) `cfg.overrides` gives them `cardMode: single` + a viewport;
  `LoadingState` and `SkeletonCard` use `cardMode: column` (wide stories).

## Re-sync risks (watch-list for the next run)

- **`.design-sync/tokens-root.css` mirrors the `[data-theme="light"]` block of `frontend/src/styles/globals.css`.**
  If that block's values change, the lifted `:root` tokens go stale — re-copy them. (We lift light→`:root` so vars
  resolve for preview cards / designs / portals that have no `[data-theme]` ancestor.)
- `cfg.cssEntry` is regenerated by `buildCmd`; the Tailwind `--content` glob in `build-css.sh` lists the 6 component
  files — if a curated component moves or a new one is added, update that glob too.
- Inter loads from a CDN `@import` (jsdelivr fontsource) in `tokens-root.css`; offline renders fall back to system
  fonts. `cfg.runtimeFontPrefixes: ["Inter"]` suppresses `[FONT_MISSING]`.
- Curated component names are pinned in `cfg.componentSrcMap` (the allowlist, since there's no `.d.ts` to enumerate
  exports). Adding/removing a component means editing both `ds-entry.tsx` and `componentSrcMap`.
