## 1. 本轮目标与边界

目标：把已有研究证据可靠地转成完整、切题且状态真实的报告，确保页面、导出、持久化正文和核验绑定同一版本。先消除“后半程做了大量工作，但页面仍是旧综合”的交付缺陷，为下一轮研究档案改造建立稳定出口。

本轮只处理：草稿契约、引用归一、独立写作、正文版本选择、有限核验、前端状态与导出一致性。研究2/5/10及最新run1作为历史失败样本，不能假设VPN修复后这些历史快照会自动恢复全文。

不处理：召回200/500/1000目标、按六维重构研究档案、选材算法、逐篇提取循环、主题聚类、全文来源扩展、模型更换、整个v2执行器。以上仍可能影响研究质量和耗时，本轮不承诺消除48分钟总耗时。

## 3. 目标链路

已有证据 → 准备回答证据包 → 直接生成草稿 → 契约/引用归一 → 核验 → 最多一次修订 → 冻结交付版本 → 页面与导出读取同一版本。

本轮只替换最终报告循环，前面的检索、计量、提取仍保留。前置综合若因其他视图需要仍运行，也只作为独立预览，不再自动填充最终报告。最终报告路径不再固定生成两份视角草稿，避免重复写作；不能把这些提案当证据。

### 3.1 证据包

- 输入用户原问题、已有subquestions、覆盖状态、稳定证据ID、完整必要摘录和来源/适用条件。
- 由程序按现有子问题整理，去重后提供有界证据包；不重新搜索、不改变原选材名单。
- 每个条目结构完整，禁止先给ID再把对应摘录截成无法核验的句子。超过上下文时减少条目并记录未读数量；长证据按真实位置分片，保留可继续读取的标识。
- 若关键材料超长，可在准备阶段有限补读已有证据；不得让写作节点无限导航索引。
- 无可用事实证据时输出确定性的材料/失败说明，标记unavailable；不启动凭记忆写领域结论。

### 3.2 草稿契约与兼容

新增内部ReportDraft，包含完整summary/findings/limitations/gaps/novelty及claims。每条叙述项采用 `{text, evidence_ids, subquestion_id?, role?, statement_kind}`；statement_kind区分事实、综合推断、研究过程说明。summary可由多个同结构段落组成，避免只有大段字符串却无法定位引用。

兼容旧模型响应：

1. 字符串列表转为text条目，已存在数字引用通过冻结citation_map回查；不能猜测没有出处的文字来源。
2. 已知对象形式 `{content,...}` 明确映射到text，保留role/subquestion_id与有效引用。
3. 未知对象、空content、无效类型、超长字段返回 `DRAFT_SCHEMA_INVALID` 与具体字段路径；最多一次定向修复。
4. `accepted` 仅表示结构接收成功；回执返回received/accepted/rejected数量及原因。不允许输入8条、保存0条还只返回成功。
5. 不为满足协议静默截断正文。超过预算明确要求缩写重交，或将完整文本保存在产物中；卡片预览另生成，不影响导出。

缺引用的事实保留为待修复草稿条目，不直接获得可引用资格；过程说明如“本次未获取全文”由运行记录支持，不强迫引用论文。推断必须有证据与范围说明，不把所有推断都视为错误。

### 3.3 引用和展示编号

内部以evidence_id引用；程序通过evidence→paper_key→冻结参考文献编号生成 `[n]`。旧数字引用只有在当前citation_map中存在才可接受；未知ev_*、越界编号、跨run证据、被排除材料均返回 `UNKNOWN_EVIDENCE_REFERENCE`，不得删除后继续当成合法引用。

同一论文的多条证据在显示上可共用编号，但claims保留具体evidence_ids。审计使用完整证据片段，不能仅拿论文标题或已生成的摘要核验。

### 3.4 独立写作与交付状态

由程序直接调用write_report，不再让模型先输出inspect/submit/finish才能写作。准备阶段达到预算、无新增信息、缺全文时均进入写作或明确unavailable，除非用户暂停/取消。

只进行一次初稿生成和最多一次有界修复/修订，修复结构与修复事实共享该额度，不层层各开一次重试。模型调用仍走现有LLM Core；其底层重试受本阶段deadline限制。

新版本字段建议：

- `delivery_status`: ready / partial / unavailable。
- `narrative_source`: final_draft / preliminary / none。
- `revision_id`、`evidence_version`、`citation_map_version`。
- `quality_status`: 沿用unchecked/internally_checked/needs_review等既有枚举。
- `failure_stage/error_code`：使生成失败、引用无效和审计超时可区分。

新运行只有原始预览而无有效终稿时，将其标注为preliminary独立展示，不能伪装成最终报告。已有成功revision重生成失败时，保留已选旧版本并展示本次尝试失败，不覆写原报告。可读但未完全核验的新草稿可保存为partial/needs_review供查看；选择/显示必须明确其状态和版本。

结构化条目与原始草稿保留；为兼容现有前端，可将完整文本投影到既有 `summary: str` 和 `findings: str[]`，不得把新对象直接塞给旧渲染器。

### 3.5 核验与版本绑定

- 程序先检查引用存在性、证据归属及版本。语义核验只对该候选交付正文执行。
- 从实际完整正文分段核验；模型提供的claims只是提示，不能省略claims未覆盖的事实。正文各段与实验比较表断言均需在coverage清单中记录。
- 建议初始实验配置：单批3–5条短断言或一个有界段落，并发最多2；每批不超过30秒，整个最终写作/审计阶段不超过180秒。均为待实测上限，不是质量承诺。
- 分批结果即时保存；超时后不原样重跑全文。若还有额度，仅允许对失败批缩小范围重试一次，并计入总deadline；额度不足直接partial。
- 绑定项包括规范交付文本hash、证据版本、引用映射版本、审计配置版本与范围。网页/Markdown/HTML从同一正文模型渲染，排版差异不混入语义hash。
- 改写部分必须重新核验；未改动部分仅在文本、证据、引用及审计配置均兼容时复用。合并后重新验证整稿覆盖，没有覆盖到的文字不能默认为非事实。
- 审计超时保存草稿及已完成核验，support_rate在覆盖不完整时保持null，不把unsupported_count=0当通过。
- 所有事实已覆盖、引用有效、无不支持/矛盾断言且版本绑定有效时，才标internally_checked。同模型复核不称独立人工验证。

## 5. 实施顺序与每步退出标准

1. **冻结基线**：保存最新run1实际报告、现有证据、提交草稿和原始引用映射，记录哈希。冻结材料用于隔离测试，不重新检索。退出：能离线复现8条findings丢失和旧summary留存。
2. **修复契约与引用**：加入纯函数归一及映射、显式反馈、旧类型投影。退出：8条对象findings完整保存，未知引用明确失败，旧字符串兼容。
3. **替换交付控制**：接入直接写作、候选revision、preview区分，禁止混合旧summary和新审计。退出：已有证据的阅读停止不会直接留下空最终页；写作失败有明确终态。
4. **分批核验与恢复**：保存部分结果、按版本绑定、一次修订/全局deadline。退出：超时保留内容且不显示通过，已完成批次不被盲目重跑。
5. **页面和导出对齐**：同一revision统一渲染，旧报告可读。退出：浏览器页面、JSON、Markdown、HTML正文内容与引用对应一致。
6. **固定材料对照**：先纯离线故障测试，再在实施任务明确的额度内用同模型、同证据包各生成新旧结果。退出：证据与历史run不变，交付缺陷消除，记录实际调用/耗时/内容支持，不宣称已修复选材质量。

VPN修复后的新全文测试属于另一个数据条件，单独记录，不能与旧摘要基线混为同材料对照。本轮编写计划不启动任何真实模型实验。
