## 2. 待修复问题（按优先级）

`from ..models.recall` 解析到不存在的 `backend.services.models`，应使用项目真实模型路径。直接离线调用 `_default_search_one('arxiv', ...)`，在发出网络请求前得到 `ModuleNotFoundError: No module named 'backend.services.models'`。外层 gather 将异常转为 0 命中，整引擎仍成功，旧路径回退不会启动。

### F2 · P1：排除策略在新引擎的模型调用之后才生效

位置：`recall_engine.py:373`、`:388`、`:430`；调用方在 `explorer.py:1518` 才 apply_exclusions。

新引擎没有应用 active_exclusions。被排除论文会计入目标量、进入规划员标题样本及摘要筛选提示词，并参与裁剪。之后删除最终论文不能撤回已污染的规划决策。离线设置排除标题 paper 1，规划员输入仍包含 paper 1。

验收：候选去重后、任何模型输入/补摘要/目标计数/裁剪前统一过滤；测试 DOI、arXiv 版本和标题排除，同时断言所有模型输入与最终语料均无目标身份。

### F3 · P1：无摘要候选直接成为正式语料，被引排序放大无关材料

位置：`recall_engine.py:211–214`、`:430–438`。

无摘要论文完全绕过筛选，直接进入最终双轨裁剪及后续计量。论文缺摘要不代表相关；又因为两条裁剪轨均依赖引用量，高被引无关论文特别容易占据前排。应保留为待判候选，执行标题/主题初筛、补充材料，明确区分 confirmed/rejected/unknown；unknown 不应无标记地进入领域统计。

#9 筛选中 47 篇无摘要直接放行，最终 45 篇仍无摘要。COVID-19 社会行为、可持续转型、鼠基因组等论文进入正式材料；前 8 篇全部无摘要。此问题不是仅假设模型可能误判，而是实际绕过模型判断。

验收：高被引跨域无摘要候选不能挤掉相关候选；筛选失败可保留原始材料，但必须标记不确定并限制其统计/结论用途。

### F4 · P2：目标量在筛选之前判断，质量筛选后不足不补搜

### F5 · P2：经典请求放在逐关键词循环中重复发射

## 3. 其余重点的审查结论

- **双轨配额**：偶数目标下能够填满两个不同论文配额，重复 key 不重复选取；未发现越界。但年均被引并不是近期论文配额，两个轨道仍可能都由旧文献占据。无裁剪时返回顺序实际是总被引排序。相关性必须先于引用偏好，并披露采样限制。
- **闭包时序**：常规路径 source_warnings、preflight_healths 均在首个 persist_sources 前初始化；没有证据说明正常路径存在闭包未赋值崩溃。但持久化的是阶段末 sources，召回中间失败仍无法恢复引擎局部候选/轨迹；进程崩溃与取消也不等价于普通 Exception。
- **阶段状态**：synthesize/report 异常被捕获后时间线仍默认 completed；persist 在数据库提交前即标 completed，提交失败时无法被“仅闭合未结束行”的错误分支改成 failed。应区分成功、部分完成、失败、跳过，并在成功提交后确认持久化结果。
- **历史与当前差异**：#9 保存的 persist 时间线仍为 running，但当前代码已在该阶段提交前调用 _stage_end。故 #9 不是当前文件每一行的精确回归证明，不能把其 running 现象直接认定为当前代码仍会同样发生。
- **下载预算**：不是全语料无限下载，而是最多选中 12/32/48 篇全部尝试。45 秒 deadline 建立在 DOI 地址解析之后（解析另有 18 秒），PDF 解析 to_thread 不在该 deadline 内；3 个槽位由下载和提取共用。因此“45秒×篇数÷3”不是阶段最坏时间保证。模型决策每轮可至120秒，提取另有关系复核，整体可能达小时量级；应设置单篇与整阶段预算、独立下载并发、及时保存已完成证据。
- **无进展判定**：inspect_material 每次增加计数，反复读同一材料仍算进展，轮次上限有效但无进展熔断不代表新增证据。应使用实际新段落/新证据/新增覆盖做 marker。
- **Token 台账**：离线 gather 10 个子任务实测同一阶段 calls=10、input=20、output=10，ContextVar 继承并共享 dict 在这里成立。它目前是成功非流式响应的 usage 汇总，不是完整计费账本；无 usage 记零、stream 不记、Anthropic cache usage 未分项。start 不返回 reset token，结束未 reset，建议改作用域管理。所谓“零开销”应改为未启用时一次 ContextVar 查询的低开销。已有 no-ledger 测试只检查空字典报告，不能证明真实上下文没有激活台账。

建议实施次序：

1. **先修 F1–F8，补真实适配边界与故障用例。** 保留 #9 原始快照，不重写旧报告。不要以测试数量代替质量验证。
