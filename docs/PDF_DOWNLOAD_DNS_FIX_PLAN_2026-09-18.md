不能根据 `198.18.0.x` 单独断定某个代理软件，也不能断言所有论文修复后都可下载。

## 2. 期望目标

1. 允许合法、公开可访问的学术PDF经过现有安全检查正常下载并解析出正文。
2. 将DNS地址拦截、解析失败、连接失败、HTTP拒绝、非PDF等状态明确区分，日志与研究记录可相互核对。
3. 相同DNS阻断不进入HTTP重试或反复尝试同一地址；本次运行保留失败原因并正常回退摘要。
4. 继续拒绝本地、私网、链路本地等非公网目标，且每次HTTP重定向与HTML提取出的PDF地址都重新校验。
5. 不更改历史研究数据，不触发全量研究、论文提取或真实LLM调用来验证下载修复。

## 4. 实施步骤与阶段出口

### A. 只读复现与确认网络路径

- 使用后端实际Python进程所在环境解析3个已失败域名，记录域名、时间、地址和校验结论。
- 检查当前下载客户端、环境变量与系统代理的生效方式；仅记录代理是否生效、类型和脱敏端点，不打印凭据或完整配置。
- 核查实际DNS配置中是否存在fake-IP规则；未确认之前保持“疑似”表述。
- 用同一条合法PDF链接比较安全校验与实际传输路径，不能拿浏览器打开成功代替后端成功。

出口：明确失败发生于哪一阶段、由哪个实际配置造成；如果无法确认来源，不靠修改IP允许列表试错。

### B. 最小环境调整

- 优先在已确认的代理中，为本次论文域名配置真实解析规则；实际出版商/CDN重定向域名按观察到的链路逐个纳入，不预设全网通配。
- 调整后重新测试后端实际解析与请求；需要重启进程/刷新解析缓存时，只处理相关组件。
- 保留原始主机名、HTTPS证书校验和逐跳URL校验，不用替换IP、关闭TLS验证或跳过DNS检查来强行成功。
- 显式输入的 `http://198.18.0.x` 仍然必须被拒绝。若传输和校验使用不同DNS视图，必须先消除路径差异，不能把一次外部解析成功当成最终连接安全的证明。

出口：至少一条已确认公开可用的PDF可由后端完整下载、验证魔数并解析出正文。若后续HTTP返回403/404等，单独归类，不能继续算DNS故障。

### C. 结构化失败反馈

建议新增内部 `DownloadResult`，字段为：

- `status`：available / unavailable。
- `path`：成功时为临时PDF路径，失败为空。
- `attempts[]`：包含 `host/stage/error_code/http_status/retryable/elapsed_ms`。
- `stage`：resolve / validate / connect / response / content。
- `error_code`：`DNS_RESOLUTION_FAILED`、`NON_PUBLIC_ADDRESS_BLOCKED`、`NETWORK_TIMEOUT`、`NETWORK_ERROR`、`HTTP_ACCESS_DENIED`、`HTTP_NOT_FOUND`、`HTTP_RATE_LIMITED`、`HTTP_ERROR`、`NON_PDF_CONTENT`、`EMPTY_TEXT`。

错误码只是原因；`NON_PUBLIC_ADDRESS_BLOCKED` 不能自动改名为“代理错误”。解析地址可在本地诊断中保存，但外显URL不包含用户信息、查询参数中的令牌、请求头或密钥。

兼容方式：保留 `download_pdf(...) -> Optional[str]` 为包装器；新内部入口提供详细结果，报告下载审计改用详细入口。先检索全部调用者，避免一次性改变其他模块的返回类型。PDF下载成功但解析空文本由解析消费层记 `EMPTY_TEXT`，不能冒充网络失败。

可重试的超时/429沿用现有有界策略；非公网阻断、鉴权拒绝、无效URL不重试同一路径。不得增加一层未计入现有预算的重试。失败仍可回退摘要，但需保留原因。

出口：研究记录能直接显示 `validate / NON_PUBLIC_ADDRESS_BLOCKED`，无需依赖仅保留最近500条的日志缓存猜原因。

### D. 验证与记录

先运行离线回归，再做不调用LLM的小规模真实下载验证。对原32篇只选择明确公开可用的代表样本，不为本次验证重跑整次研究。

真实验证需覆盖arXiv与另一个合法开放获取来源，分别记录：解析结果、HTTP状态、PDF魔数、正文是否非空、耗时、失败原因。成功下载的测试文件验证后清理；只保存诊断结果，不覆盖历史材料。若一个来源独立不可用，明确标为未验证，不用另一个来源成功宣称全部修复。

## 5. 验收标准

| 验证场景 | 必须达到的结果 |
|---|---|
| 域名解析到198.18.0.x | 不发目标HTTP请求；结构化返回非公网阻断 |
| 调整后域名解析为公网、来源提供合法PDF | 后端可下载并解析非空正文 |
| 同一域名解析同时包含公网和非公网地址 | 拒绝，不只挑一个公网结果放行 |
| URL直接指向localhost/私网/链路本地或198.18地址 | 继续拒绝 |
| 公网入口重定向到非公网目标 | 在下一跳请求前拒绝 |
| HTML中的PDF地址指向非公网目标 | 拒绝，不绕过URL校验 |
| URL携带用户凭据或非法协议 | 继续拒绝 |
| 排除论文或重定向到排除身份 | 原排除机制继续生效 |
| 来源403、429、超时、非PDF或空文本 | 分别记录实际原因，不统一变成DNS错误 |
| 失败或取消时产生临时文件 | 清理文件，不遗留成功状态 |
| 旧下载调用者 | Optional路径接口保持兼容 |
| 历史run1 | 报告、证据和状态保持不变 |

本次完成的定义是“确认并消除实际环境中的DNS阻断，保留安全边界，失败原因可追踪”。不要求32篇全部成功，不承诺整体研究变快到某个时长，也不以PDF魔数通过代替正文解析成功。
