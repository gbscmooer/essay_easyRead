# 深度研究系统重设计 — 面向学者的多关系研究地图

> **状态：已被 v3.0.0 取代，保留作背景资料，不要按本文实现。**
>
> 本文提出的路线是"把 facet 的每个维度拆成独立 typed 边（same-purpose / same-method
> / same-dataset）"。v3.0.0 走的是相反且更简单的路线：**只有一条 `related` 边、一套
> 关联度算法**（`backend/services/deep_research/graphkit/relatedness.py`），八个通道
> 融合成一个分数，同一个分数决定连边 / 社区 / 重要性 / 图检索；"为什么相关"由边上的
> `detail.components`（每通道 sim × weight → contribution + 理由 + 共享项）回答，
> 信息量与拆边等价，但不会让图谱边数翻好几倍、也不用在多套打分之间做取舍。
>
> 本文 1.2 节列的痛点（单一分数没信息量）依然成立，v3 用可解释分解而非拆边来解决。

> 状态：**设计草案，待确认**。本文档用于在动手前对齐"深度研究"模块的目标、输出形态与技术路线。

## 一、问题与定位

### 1.1 它到底帮学者做什么

输入：工作区里少量（2-3 篇）种子论文。
目标：帮学者——**尤其是刚进入一个领域的新人**——快速看清这个方向，并辅助科研决策。具体三个场景：

- **场景 A｜领域速览**：这个方向有哪些核心论文？分成哪几个子主题？大家都在用什么方法/数据集？研究怎么随时间演化？
- **场景 B｜idea 查重**："我想做的这个点子，有没有人做过？谁做的、怎么做的？" —— 找出**同目的且同方法**的工作。
- **场景 C｜思路扩展**：按关键词/方向切入，找到相关工作，**发现自己没想到的同类思路**（哪怕这些论文彼此不互相引用）。

### 1.2 核心痛点（当前系统的问题）

现在图谱里论文之间只有一条 `similar` 边，**它是一个被加权压扁的单一分数，没有信息量**：

- 学者看到两篇"相似"，但**不知道为什么相似**——是研究目的像？方法像？还是用了同一个数据集？
- 单一分数无法支撑上面任何一个场景：查 idea 需要"同目的 + 同方法"，找思路需要"同目的但方法不同"，这些都要求**区分相关的维度**。

### 1.3 核心理念转变：单一相似度 → 多关系（multi-relation）

把"两篇论文有多像"拆成**多种带类型、可解释、可筛选的关系**，每条关系回答学者的一个具体问题。

> 关键事实：`similarity/facet_weighted.py` **已经**把相似度算成了 目的/方法/baseline/数据集 四个维度，只是 `graph_builder` 又把它们加权合并成一条 `similar` 边。**本次重设计的本质 = 不再合并，把每个维度作为独立关系暴露出来。** 复用已有计算，风险低。

## 二、关系类型设计（系统的核心）

| 关系类型 | 含义（回答什么问题） | 计算依据（已有数据） | 需不需要互引 | 状态 |
|---|---|---|---|---|
| **same-purpose 同目的** | "在解决同一个问题/同一方向" | `problem` + `one_sentence` + `key_contributions` 语义相似 | **不需要** ✅ | facet 已算，未独立暴露 |
| **same-method 同方法** | "用了类似的方法/思路" | `method.overview` + `pipeline` 语义相似 | 不需要 | facet 已算，未独立暴露 |
| **same-dataset 同数据集** | "在同一批数据上做实验" | `experiments.datasets` 集合重叠 | 不需要 | facet 已算（Jaccard） |
| **same-baseline 同基线** | "对比了相同的基线方法" | `experiments.baselines` 集合重叠 | 不需要 | facet 已算（Jaccard） |
| **cites 引用** | "A 直接引用了 B" | `parent_paper_id` | — | ✅ 已实现 |
| **co-citation 共被引** | "A、B 经常被同一批论文一起引用" | 引用结构 | — | ❌ 待加（强信号） |
| **bibliographic-coupling 文献耦合** | "A、B 引用了大量相同的文献" | 引用结构 | — | `bibcoupling` provider 已有 |

设计原则：
1. **每条边都带 `kind`（关系类型）+ `score` + `reason`（为什么）**，前端可按类型筛选、点开看理由。这是把 `facet_weighted` 已有的 `details` 分解直接挂到独立的边上。
2. **"同目的"是回应"找到不互引的同类思路"的关键**——它纯靠语义，完全不依赖引用关系。
3. 学者通过**勾选关心的关系类型**来过滤图谱（已有 `EdgeFilter` 组件，扩展选项即可）。

## 三、三个核心场景的具体输出形态

### 场景 A｜领域速览（新人 onboarding）

进入研究页，除了中间的图谱，**右侧新增「领域速览」面板**：

- **关键论文 Top N**：按中心性（PageRank）排序——"想入门先读这几篇"
- **子主题列表**：每个社区一行 = `簇标签 + 论文数 + LLM 一句话总结`——"这领域分这么几个方向，各在干嘛"（社区发现已有，**LLM 簇总结待加，是杀手锏**）
- **领域共性**：高频方法 / 高频数据集 / 高频基线（直接聚合 `method`/`datasets`/`baselines`）
- **时间轴**（可选）：各子主题随年份的论文数量，看研究趋势（`year` 字段现成）

### 场景 B｜idea 查重

输入框："描述你的 idea（目的 + 打算用的方法）" →
系统把输入 embedding 后，在图里找 **same-purpose 高 且 same-method 高** 的论文 →
输出："找到 K 篇高度重合的工作"，每篇标注目的相似度/方法相似度/年份/链接 →
帮学者判断"被做过了 / 还是个空白 / 有人做了但方法不同（机会点）"。

> 复用：RAG 已有向量检索（`RagQueryBox`）；这里是**带 facet 约束的检索**，不是自由问答。

### 场景 C｜关键词/方向探索

输入关键词或一段方向描述 → 高亮/抽取相关子图 + 相关簇 →
学者沿 **same-purpose** 边滚雪球，发现彼此不互引、但目标一致的多种思路。

## 五、分阶段实施（与毕设主线对齐）

> 顺序已按确认调整：**领域速览面板先做**（价值最直接，且大部分依赖现有数据，不必等拆边）。

- **阶段 1｜领域速览面板（首个交付）** ⭐：关键论文(PageRank 已有) + 子主题 LLM 一句话总结(新增) + 领域共性聚合(method/datasets/baselines 现成) +（可选）时间轴(year 现成)。直接交付"帮新人理解"的价值。
- **阶段 2｜多关系图谱（地基）**：拆边——facet **四维核心关系**(same-purpose/same-method/same-dataset/cites)独立成边 + 关系类型筛选。把"单一 similar"在已解读论文间替换掉。
- **阶段 3｜idea 查重 + 关键词探索**：facet 约束检索 + 关键词入口。
- **阶段 4｜量化评测（毕设论文核心）**：见下。

## 六、量化评测（毕设 Phase C，目标已给出靶子）

目标清晰后，评测就有了对象：

- **关系准确性**：人工标注若干论文对的真实关系（同目的？同方法？），算各类关系边的 **Precision@k**——证明"多关系"比"单一 similar"更准、更有信息量。
- **关键论文命中率**：系统给的 Top-N 关键论文 vs 该领域公认高被引论文的命中率。
- **子主题聚类质量**：modularity / 与人工划分的 NMI（可用 `cdlib`）。
- **场景有效性（可选小型用户实验）**：新人借助领域速览，能否正确说出领域的关键论文与子方向。

## 七、决策记录

**已确认（2026-06）：**
1. ✅ **关系类型范围**：第一阶段先做 4 种核心 `same-purpose / same-method / same-dataset / cites`（复用 facet_weighted 已有计算）。co-citation / bibcoupling / same-baseline 后续再加。
2. ✅ **首个交付**：**领域速览面板**（不必等拆边，依赖现有数据即可，价值最直接）。
3. ✅ **叶子论文（未解读的联网扩展）**：只用 **cites** 关系连入图谱；不参与 same-purpose/method/dataset 等语义关系（这些只在已解读论文间计算）。
4. ✅（推论）**单一 `similar` 边**：已解读论文间被四维 typed 关系替换；叶子论文仅用 cites，不再依赖 bge similar 兜底。

**仍待确认：**
5. **"same-purpose 同目的"是否设为图谱默认展示的主关系**（其余关系靠 EdgeFilter 勾选）？
6. **idea 查重**的输入形态：自然语言一段描述，还是结构化（目的框 + 方法框）？
7. 毕设论文定位措辞："面向学者的多关系研究地图"是否准确？
