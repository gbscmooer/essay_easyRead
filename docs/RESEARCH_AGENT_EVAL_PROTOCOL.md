# 研究 Agent Harness 对照实验协议（草案 v0.1）

> 状态：阶段 0 冻结稿。后续工具开发、workflow 实现与论文实验均以此为准。  
> 主假设：在固定学术文献研究任务上，`特化 harness + DeepSeek` 优于 `Codex/Claude Code + 仅 goal（不接本系统 MCP/软件）`。

---

## 1. 实验目的

验证**产品级**问题，而非「同工具下比模型智商」：

| 组别 | 设置 | 模拟的真实用户 |
|------|------|----------------|
| **A（基线）** | Codex 或 Claude Code，只给同一 `goal`，可联网/可写临时脚本，**不安装、不接入本仓库工具** | 只有通用 coding agent 的用户 |
| **B（本系统）** | 本项目研究 Agent Harness + DeepSeek，只给同一 `goal` | 使用本特化产品的用户 |

可选辅实验（阶段 4 有余力再做，不阻塞主线）：

| 组别 | 设置 | 回答的问题 |
|------|------|------------|
| C | Claude Code + 本系统 MCP，但无强制 workflow | 增益来自工具还是编排？ |
| D | 本 harness + 更强模型 | 增益是否主要来自 harness？ |

---

## 2. 非目标（写进开题，避免范围膨胀）

- 不宣称全面替代 Codex/Claude Code（仅文献研究任务级对比）
- 不做大规模引文图谱 IR 标注评测
- 不实现公式↔代码双向映射、3D 图谱
- 不把整个论文精读 Web 重做一遍

## 3. 标准任务卡（主实验固定 3 个）

每张卡开跑前打印/粘贴给 A、B，**文字不得因组别改写**。  
成功标准以「交付物检查清单」为准，过程步骤不计入「完成」。

### T1 — 种子主题精读包

```text
Goal:
我正在调研「检索增强生成（RAG）在学术文献问答中的应用」。
请基于公开网络与你能获得的资料，整理一份精读包：
1) 选出 3–5 篇最相关的代表性论文（给出标题、年份、链接或标识）；
2) 对每篇给出：核心贡献、方法要点、实验设置摘要、局限；
3) 最后给出 5 条可执行的后续阅读建议。

约束：
- 不要写空泛科普；结论尽量对应到具体论文。
- 若某条信息不确定，明确标注「不确定/未找到」。
- 最终交付一份结构化 Markdown 报告。
```

**完成检查清单**

- [ ] 论文数量在 3–5
- [ ] 每篇含贡献 / 方法 / 实验 / 局限四块
- [ ] 有后续阅读建议 ≥5 条
- [ ] 无依据处有不确定标注（或提供可核验引用）

### T2 — 工作区扩展与阅读路径

```text
Goal:
假设我已有一个关于「多模态大模型视觉定位（visual grounding）」的小型文献集合
（运行时由实验员提供：本地工作区 ID / 论文列表文件，A/B 获得等价信息）。
请完成：
1) 识别集合内的核心种子论文与明显缺口；
2) 提出应补充的相关论文方向或具体候选（至少 5 个）；
3) 给出分阶段阅读路径（先读什么、后读什么），并说明排序理由
   （引用依赖 / 方法基础 / 时间线等）。

约束：
- 路径必须覆盖给定集合中的主要论文；
- 每阶段用 1–2 句说明「为什么现在读这些」；
- 最终交付结构化 Markdown（含路径表）。
```

**完成检查清单**

- [ ] 指出种子与缺口
- [ ] 补充候选 ≥5
- [ ] 阅读路径分阶段且覆盖主论文
- [ ] 每阶段有排序理由

### T3 — 证据约束的综述草稿

```text
Goal:
基于给定工作区论文（运行时由实验员提供等价材料），撰写一份短综述草稿：
1) 用表格对比各论文的任务、方法、数据/基准、主要结果、局限；
2) 写 800–1500 字综述正文，分段组织；
3) 正文中每个关键论断必须能回溯到某篇论文（用标题或 ID 标注）；
4) 对缺乏证据支持的句子单独列出「待核实假设」。

约束：
- 禁止无来源地编造实验结果数值；
- 若材料不足以支持某结论，写入「待核实假设」，不要硬写。
- 最终交付：对比表 + 综述正文 + 待核实列表。
```

**完成检查清单**

- [ ] 对比表含任务/方法/数据/结果/局限
- [ ] 正文长度大致达标
- [ ] 关键论断有论文回溯标注
- [ ] 有「待核实假设」列表（可为空，但字段必须存在）

## 4. 评分表

每组、每任务、每轮独立打分。建议每任务至少跑 **3 轮**（换随机种子/新会话）。

### 4.1 客观项（0/1 或比例）

| 指标 | 定义 | 计分 |
|------|------|------|
| 任务完成率 | 检查清单条目通过数 / 总条目数 | 0–1 |
| 必要步骤覆盖 | 见下表「必要能力」是否出现在产物中 | 0–1 |
| 证据引用率 | 带论文回溯的论断数 / 关键论断数（T3 为主；T1/T2 有则记） | 0–1 |
| 无依据句比例 | 抽查 10 条陈述中无法回溯来源的比例（越低越好） | 0–1 |
| 超时/崩溃 | 是否在时限内给出最终报告 | 0/1 |

**必要能力（用于「必要步骤覆盖」）**

| 任务 | 必要能力 |
|------|----------|
| T1 | 选篇、结构化精读字段、阅读建议 |
| T2 | 缺口分析、扩展候选、分阶段路径+理由 |
| T3 | 对比矩阵、综述正文、论断回溯、待核实列表 |

### 4.2 主观项（人工 1–5）

| 指标 | 1 | 3 | 5 |
|------|---|---|---|
| 可用性 | 几乎不能用 | 能用但需大改 | 可直接当草稿 |
| 专业可信度 | 明显外行/胡编 | 大体正确有硬伤 | 同领域可读 |

打分时 A/B 产物匿名乱序，避免偏见。

### 4.3 成本项（记录，不强制当主结论）

- 墙钟时间
- 估算费用（若可得）
- 人工介入次数（A/B 均允许澄清一次 goal，超出记介入）

### 4.4 汇总方式

- 主结论看：**任务完成率** 与 **可用性** 的任务均值  
- 次看：证据引用率、无依据句比例  
- 单任务 B 输、整体 B 赢 → 仍可成立，论文中如实写失败案例

## 5. 运行规范（保证对照公平）

1. **同 goal**：复制任务卡原文，禁止为某组「优化提示词」。  
2. **A 组环境**：官方 CLI/IDE agent 即可；可联网；**禁止**配置本仓库 MCP、API token、本地 `essay-agent`。  
3. **B 组环境**：仅通过本 harness 入口提交 goal（CLI 或 Web）；模型固定 DeepSeek（版本记入实验日志）。  
4. **材料等价**：T2/T3 给 A 的「论文列表/PDF/摘要包」与 B 工作区内可见信息等价；不得只给 B 已解析好的隐藏字段却不给 A。  
   - 过渡期若 B 尚未具备 ingest：可对 A 提供与 B 工作区导出一致的 PDF+标题列表。  
5. **时限**：建议每轮 **45 分钟**；超时记未完成，保留部分产物另表。  
6. **记录**：保存 goal、完整对话/journal、最终 Markdown、耗时、模型/agent 版本。

## 8. Harness 试做结论（2026-07-19）

已落地最小可运行 harness（**无需 LLM**）：

- 服务：`backend/services/research_harness.py`
- 入口：`POST /api/agent-tools/runs`，CLI：`python -m backend.research_agent`
- Workflow：`literature_brief`、`survey_path`
- 新工具：`reading_plan_build`、`survey_build`

**难度判断（当前）**

| 块 | 难度 | 说明 |
|----|------|------|
| 工具封装 + 状态机 + journal/产物 | **低–中** | 复用现有 planner/agent_tools，1 个迭代可跑通 |
| 证据检索依赖向量索引 | **中** | 无索引时 soft-fail，不影响主流程 |
| 真正「只给 goal、自动找网/导入论文」 | **高** | 尚未做 ingest/expand；对照 A 时 B 仍需预置工作区 |
| 接入 DeepSeek tool-calling 替代 parse_goal | **中** | 编排层已就绪，差模型路由与重试策略 |
| 产品级打赢 Codex 全托管 | **高** | 取决于 ingest + 联网扩展，不只 harness 壳 |

**建议**：继续做 harness，但下一刀优先 `parse_goal` 模型化 + 工作区预置剧本；全自动 ingest 可作为第二阶段，避免范围失控。
