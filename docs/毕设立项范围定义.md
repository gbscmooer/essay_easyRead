# 毕业设计题目立项范围定义

> 用途：报导师审题、毕设系统选题表填写素材、开题报告的基础范围定义。
> 状态：v1（2026-09-01），经导师同意后按反馈修订。

## 题目

**基于引文网络与多源融合的领域文献全景分析与热点发现系统**

备选（导师认为偏大时）：《面向科研领域的文献发现、关联分析与热点可视化系统设计与实现》

---

## 一、选题背景与问题定义

研究者进入一个陌生领域时面临三个痛点：

1. **文献分散**：同一领域的文献散落在 arXiv、Semantic Scholar、CrossRef 等多个数据源，检索口径各异，人工汇总费时。
2. **结构不可见**：引文数据库能返回列表，但领域内部的派系结构（子方向社区）、奠基性文献与新兴主题的演化关系不可见，需要靠长期阅读积累直觉。
3. **工具割裂**：CiteSpace、VOSviewer 等计量工具能做共现分析但需要用户自行准备数据、无语义理解；ReadPaper、知云等阅读类应用以单篇精读为主，缺领域视角。从「了解领域」到「精读论文」之间没有连贯的工具链。

本系统以「领域大观」为核心：输入领域关键词或种子论文，自动完成多源检索、引文扩展、关联度计算与图谱构建，以热力图和热点榜单呈现领域结构与演化，并支持批量下载与精读，形成「发现 → 全景 → 热点 → 精读」的完整闭环。

## 二、建设目标

1. **领域发现**：从关键词/种子论文出发，融合多个学术数据源收集文献，经引文扩展形成领域文献集（目标规模：单领域 100–500 篇）。
2. **全景分析**：构建引文图谱，通过多通道关联度融合与社区划分呈现领域子方向结构，以「年份 × 子方向」热力图展示领域演化。
3. **热点发现**：基于引用增速与爆发检测输出热点文章、经典骨架、新兴主题三类榜单，辅助快速定位关键文献。
4. **闭环支持**：榜单与图谱节点可直接批量下载 PDF 并进入精读流程，配套 RAG 问答对领域知识进行检索增强问答。

## 四、范围外（不做）

明确排除，防止范围蔓延，也为答辩划定边界：

1. **不做**多用户账号体系、权限管理、公网多租户部署——单机单用户工具。
2. **不做**自研大模型或 embedding 模型——LLM 与向量化调用外部兼容 API，可配置。
3. **不做**全文级文献计量（如全文词频共现网络）——分析基于元数据、摘要与已有 PDF 解析结果。
4. **不做**订阅推送、协作分享、移动端。
5. **不做**引文数据库本地镜像——在线调用外部 API，离线场景用预置演示数据兜底。
6. **不做** Sci-Hub / Anna's Archive 等盗版渠道集成——下载只走 arXiv、Unpaywall/OpenAlex 定位的合法开放获取版本及出版商公开页面（PyPaperBot 一类工具的核心下载渠道属于此类，不采用其 SciHub 部分；答辩与论文中保持合规边界）。
7. 精读模块只修缺陷，不新增功能。

## 四A、数据源清单与选型（M1a）

设计原则：默认数据源全部走开放 API（合法、稳定、可写进论文）；Google Scholar 爬虫作为可选实验源，默认关闭。

**认证与额度（2026-09-01 实测/查证，修正早期结论）**：

- **OpenAlex**：2025 年 2 月起废弃 mailto/polite pool，改为 API key 体系。**匿名请求日额度仅 100 credits**（约 $0.10）——大批量检索很快耗尽并返回 429，这正是「未注册大量访问被限」的来源。免费 key 只需在 openalex.org 注册约 30 秒（无需付费方式），日额度 **10 万 credits**（约 $1）且上限 100 req/s，设置页可选填。429 按官方建议指数退避，响应头 `X-RateLimit-Remaining` 可监控余量。
- **Unpaywall**：不变，零注册零 key，`email` 参数填任意真实格式邮箱即可（实测 `example.com` 域名被 422 拒绝，普通邮箱通过），额度宽松。
- arXiv / CrossRef：零注册零 key。
- 本机直连国外 API 存在**间歇性 TLS 重置**（实测三次两败一成），provider 必须带超时重试与多源回退；用户本机有代理环境则不受影响。

**额度工程：批量优先，使「大量并发分析」不等待**（针对 300–500 篇领域集的一次全景生成）：

1. **批量端点**：`filter=ids.openalex:W1|W2|...`（竖线 OR）单请求最多 **100 个 ID**，配 `per_page=100` 与 `select=` 字段裁剪（官方省额度技巧）→ 300 篇元数据 = 3 个请求，匿名额度也基本够用，配免费 key 完全无压力。
2. **引文边零额外请求**：OpenAlex 的 works 记录默认自带 `referenced_works`（该文引用的全部 OpenAlex ID）——引文图谱的边随批量元数据一并返回，**不需要逐篇抓引用列表**（S2 模式的每篇一请求是额度杀手）。
3. **SQLite 元数据缓存**：按 DOI/OpenAlex ID 落库（系统已有 DB 层），同一论文永不重复请求；领域增量扩展只请求新增 ID。
4. **客户端令牌桶限速**：provider 内置并发上限与匀速发送，从源头避免触发 429，而非被 429 后等待；收到 429 则读 `Retry-After` 指数退避并多源回退（OpenAlex → S2 → CrossRef）。
5. **时间预算**：300 篇全景的元数据阶段约 3–6 个批量请求（秒级）；PDF 下载走 Unpaywall/OA 直链与出版商站点，不占学术 API 额度，仅受网络与出版商限制。

| 数据源 | 用途 | 关键字段 | 状态 | 说明 |
|--------|------|----------|------|------|
| **OpenAlex** | 元数据 + 引用数 + 摘要 + 引文边 | `cited_by_count`、`counts_by_year`（逐年引用，热点/爆发检测核心输入）、`abstract_inverted_index`、`referenced_works`（引文图谱边，随记录返回） | **新增，第一梯队** | 2025 年第三方评估覆盖率 98.6%（高于 S2 的 98.3%）；匿名日额度 100 credits，免费 key（30 秒注册）10 万 credits/天、100 req/s；批量 filter 单请求 100 ID + select 裁剪 |
| **Unpaywall** | DOI → 合法 OA PDF 直链 | `is_oa`、`best_oa_location.url_for_pdf` | **新增，第一梯队** | 解决「非 arXiv 论文下载不到」的主路径：5 万+ 机构仓库的绿色 OA（作者自存档）；`api.unpaywall.org/v2/{doi}?email=`，免费，仅要求邮箱参数 |
| Semantic Scholar | 相关论文 / 元数据 / TLDR | citationCount、abstract、embedding | **已有** | 无 key 时全用户共享限速池，配 key 后 1 RPS；作为 OpenAlex 的补充与交叉验证 |
| arXiv | PDF 下载（预印本） | PDF 直链 | **已有** | 限速 ≥3s/请求 |
| CrossRef | DOI 元数据兜底 | abstract（部分有）、参考文献 | **已有** | polite pool 需 mailto |
| CORE | OA 全文聚合（备选） | 全文链接 | 备选，暂缓 | 与 Unpaywall 功能重叠，覆盖率不如前者时优先级低 |
| **Google Scholar（爬虫）** | 引用数补全 / GS 独有条目 | num_citations、摘要、版本链接 | **可选实验源，默认关闭** | 见下方风险说明 |
| **知网 CNKI（爬虫/MCP）** | 中文文献检索 / 下载 / 引证文献 | 题录、摘要、被引频次 | **调研后决定：不集成** | 见下方知网专项说明 |
| 万方开放平台 | 中文文献元数据（如需中文覆盖） | 题录、摘要 | **备选，仅在确需中文文献时评估** | 官方 API（`apps.wanfangdata.com.cn`），面向开发者开放，需注册 key；覆盖与知网高度重叠 |

**Google Scholar 爬虫路线调研结论（2026-09）**：

- 代表工具：`scholarly`（Python，requests 型爬虫 + 代理轮换，抓引用数/摘要/引用列表，活跃维护）、`PyPaperBot`（下载器：Google Scholar PDF 链接 + SciHub + SciDB，可选 selenium 真实 Chrome 辅助过 bot 检测）。浏览器指纹方向的相关工具为 undetected-chromedriver / curl-impersonate。
- 现实约束：GS 反爬以 **IP 频率封锁 + CAPTCHA** 为主，浏览器指纹模拟收益有限，实际可用性取决于代理池（免费代理不稳定，付费 ScraperAPI 类服务有成本）；社区反馈引用数抓取可靠性持续劣化。
- 合规约束：GS ToS 禁止自动化访问；结合第 6 条范围外约定，SciHub 渠道一律不进系统。
- **决策**：引用数与逐年趋势直接用 OpenAlex（覆盖更全、合法、含 `counts_by_year`），不依赖 GS；GS 爬虫仅在 OpenAlex/S2 数据缺失且用户显式开启时作为补全实验源，采用 scholarly + 自有代理配置，限速运行，失败静默降级。此边界写入论文「数据来源与合规性」小节。

**知网（CNKI）专项调研结论（2026-09）**：

- 生态现状：社区项目活跃。爬虫类如 `CNKI-selenium-crawler`（Selenium，爬参考文献/引证文献）、GitHub `topics/cnki` 下多个项目；MCP 类如 `cnki-mcp-server`（Playwright，pip 可装，6 个工具）、`PluginsX/Cnki-Mcp`、`CNKI-Enhanced-MCP`、`cookjohn/cnki-skills`（Claude Code 技能）等，普遍基于 Playwright/Selenium 页面模拟。知网无对个人开放的官方 API（`open.cnki.net` 开放平台面向机构合作）。
- **不集成进系统的决定性理由**：① 法律风险显著高于 GS——知网法务维权记录积极（反不正当竞争维度已有公开争议案例），批量自动化访问直接违反其服务条款；② 学校合规——本校与知网存在订阅合作关系，毕设系统出现知网爬虫依赖属于在校生违规的高暴露面；③ 技术脆弱——页面改版即失效，且「下载」实际依赖校园 IP/登录态的订阅权限；④ 答辩风险——论文与演示中出现该依赖无法自圆其说。
- 个人研究用途（不进系统、不进论文）：可自行使用社区 MCP（如 cnki-mcp-server）配合本校合法订阅、控制频率，属于个人工具链选择，与本项目交付物无关。
- 系统的中文文献需求（如有）：优先评估万方开放平台官方 API（合法、面向开发者）；本课题为 CV/ML 方向领域全景，核心文献在 arXiv/OpenAlex 覆盖内，默认不含中文库。

## 五、技术路线

- **架构**：前后端分离。前端 React 18 + TypeScript + Tailwind + Recharts（热力图）；后端 Python FastAPI + SQLModel；存储 SQLite。
- **数据流**：输入 → 多源检索（S2/arXiv/CrossRef）→ 引文解析（GROBID/正则回退）→ PDF 下载与文本分块 → 向量化 → 关联度计算与图谱构建 → 聚合（热力图/榜单）→ 前端可视化与 RAG 问答；SSE 流式推送进度。
- **关键依赖**：OpenAI 兼容 LLM API（解析/问答）、GROBID（可选，缺失时回退正则）、学术数据源公开 API。

## 六、关键技术点（论文与答辩核心）

1. **多通道论文关联度融合**：八个异构通道各自分位数归一后加权融合，权重可配置——解决不同量纲通道不可比问题。
2. **图谱骨架提取**：Disparity Filter 保留统计显著边，控制大规模图谱的视觉与检索噪声。
3. **热点识别**：引用增速 + Kleinberg 爆发检测识别热点，与高被引（经典）区分——「热度」与「经典」双维度。
4. **领域演化热力图**：年份 × 社区的发文密度聚合，呈现子方向兴衰。
5. **检索增强问答与消融评测**：纯向量 / 向量+重排 / 混合检索的对比实验（Precision@K、Recall@K、nDCG@K、MRR）。

## 七、约束与依赖

- 单机单用户运行，本地 SQLite，一键启动脚本。
- 外部 API 依赖：LLM（必须，可配置任意兼容服务商）、学术数据源（网络必需）；答辩演示准备离线预置数据 + 录屏兜底。
- 数据合规：仅采集公开学术元数据与开放获取 PDF，遵守各数据源限速条款。

- **成果**：可运行系统一套（含上述 M1–M7）、毕业论文一篇（含真实数据实验）、演示材料。
- **已有基础**：系统 V1.0（精读为主 + 初版深度研究）已完成约 5.6 万行代码（后端 Python 3.4 万行、前端 TypeScript 2.2 万行），382 项后端测试通过，已申请软件著作权（登记名「论文精读辅助分析软件 V1.0」，材料已提交）。本课题为其 V2.0 演进：重心从精读转向领域发现与全景分析。

本课题面向科研人员进入新研究领域时文献分散、领域结构不可见、发现与精读工具割裂的问题，设计并实现一个以领域全景分析为核心的文献发现系统。系统以领域关键词或种子论文为输入，融合 Semantic Scholar、arXiv、CrossRef 多个学术数据源进行检索与引文扩展，经去重与重排序形成领域文献集；在此基础上计算论文间多通道关联度（主题向量、研究目的、方法、术语、共享数据集、共享基线、文献耦合、共引八个通道），通过分位数归一与加权融合构建引文图谱，结合社区划分与 Disparity Filter 骨架提取呈现领域子方向结构；以「年份 × 子方向」热力图展示领域演化脉络，基于引用增速与爆发检测输出热点文章、经典文献、新兴主题三类榜单；榜单与图谱节点支持批量下载 PDF 并转入 AI 精读流程，配套检索增强（RAG）问答对领域文献集进行自然语言检索。系统采用前后端分离架构（React + FastAPI + SQLite），大模型能力通过可配置的兼容 API 接入。预期成果为可运行系统一套与含真实数据消融实验（Precision@K、Recall@K、nDCG、MRR 等指标）的毕业论文，为研究者快速建立领域认知提供一体化工具支撑。
