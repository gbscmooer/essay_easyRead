## 一、选题背景与意义

### 1.1 选题背景

计算机视觉与机器学习（CV/ML）等领域文献体量庞大且增长极快，研究者进入一个陌生方向时普遍面临三重困难：

**其一，文献分散、检索口径不一。** 同一主题的文献散落在 arXiv、OpenAlex、Semantic Scholar、CrossRef 等多个数据源中，各源的元数据覆盖、标识符体系与检索语法各异，人工逐一检索、汇总、去重成本极高。

**其二，「直接问大模型」不可信。** 以 GPT 类模型直接回答「这个方向现在大家都在做什么」「这个 idea 有没有人做过」时，模型依赖训练截止日期冻结的参数记忆，存在两个根本缺陷：知识过时与幻觉编造。其回答是口头概括，既不能追溯到具体文献，也无法核验，对「idea 查新」这类高利害判断是不可接受的。

**其三，工具割裂。** CiteSpace、VOSviewer 等经典文献计量工具能做共现与共引分析，但要求用户自行准备清洗数据，且不理解语义；Elicit、NotebookLM、ResearchRabbit 等新一代 AI 研究工具虽有检索与问答能力，或缺少对「领域现状」的客观统计（被引分布、演化趋势、子方向结构），或不对结论提供可点开核验的证据链；ReadPaper、知云等阅读类应用则以单篇精读为主。从「了解一个领域」到「精读一篇论文」之间缺少连贯的工具链。

### 1.2 选题意义

本课题设计并实现一个**问题驱动、证据可核验**的领域文献全景分析系统：研究者输入一句自然语言问题（如「用 AI 识别肿瘤有没有人做，做得怎样」），系统自动完成检索式拆解、多源文献召回、客观计量分析（引用统计检验、子方向聚类）与大语言模型综合，产出一份每条结论都挂接真实论文证据、附检索透明度信息的结构化调查报告，并支持 RAG 检索增强追问与单篇精读。

**实用意义**：让学者在不逐篇阅读文献的前提下快速、客观地建立领域认知，并为 idea 查新提供可核验的先行工作证据，缓解文献过载。

**学术意义**：本课题探索了一条「算法承担客观性、大模型承担可读性」的系统路线——所有领域现状判断的底层数字（被引、年份、引用速度、聚类结构）由统计与图算法算出，大模型仅对召回材料做综合解读，并辅以论断级证据核验；同时以「系统 vs 裸大模型」两臂对照评测实证该路线对幻觉暴露面的抑制。该设计对检索增强生成（RAG）在科研场景下的可信落地具有一定参考价值。

## 二、国内外研究现状

### 2.1 学术数据源与文献计量工具

学术元数据基础设施已相当成熟。商业库 Scopus（Elsevier）与 Web of Science（Clarivate）覆盖全学科、提供机构订阅接口；开放库 OpenAlex（2025 年第三方评估覆盖率约 98.6%）提供免费 API，其 works 记录自带逐年被引数（counts_by_year）与参考文献列表，可直接支撑引文网络构建；Semantic Scholar、arXiv、CrossRef 分别提供论文语义信息、预印本全文与 DOI 元数据兜底。

可视化计量方面，CiteSpace（Chen, 2006）与 VOSviewer（van Eck & Waltman, 2010）是共引/耦合分析与科学知识图谱的代表工具，burst detection（Kleinberg, 2002）等热点检测方法亦有成熟研究。但这类工具定位于分析人员手动操作：需自行导出数据、参数调试门槛高、不提供语义理解与自然语言交互，也未与大模型综合能力结合。

### 2.2 大模型驱动的学术研究工具

新一代工具有效结合了检索与大模型：Elicit 支持检索后生成研究报告与逐句引用；NotebookLM 的 Deep Research 可制订检索计划并产出带来源的报告；ResearchRabbit 以种子论文出发做相关文献发现与关系地图；OpenScholar（Asai 等，2024）面向科学问答提出了检索增强、自反馈与引用核验的系统方案，并配套 ScholarQABench 评测集。这些工作验证了「检索增强 + 大模型综合」路线的可行性，但公开资料层面均未把「领域现状的客观统计（引用显著性检验、子方向演化）」作为一等公民呈现，也未内置对生成论断的证据核验。经调研比对（2026-09），未发现与本系统流程与算法组合完全一致的公开产品；本课题不宣称全球独有，而是以「证据可核验 + 统计客观性」为可检验的差异化方向。

### 2.3 生成式文献综述的评测研究

如何科学评价大模型生成的文献综述，近两年出现了一批代表性工作：ALCE（Gao 等，EMNLP 2023）提出引用是否支持论断、需要证据的论断是否被覆盖的评测框架；SurGE（Su 等，SIGIR 2026）以专家综述参考文献测核心文献召回、以章节/句子级引用合适程度与 NLI 测引用支持；SurveyBench（Sun 等，2025）引入 quiz-based answerability，检验生成的综述能否让读者答对领域问题。这为本课题的评测体系提供了方法参照。

### 2.4 现状小结与课题切入点

| 维度 | 计量工具（CiteSpace 等） | AI 研究助手（Elicit 等） | 直接问大模型 | 本课题 |
|---|---|---|---|---|
| 知识来源 | 用户自备数据 | 在线检索 | 参数记忆（冻结） | 实时多源学术 API |
| 领域现状统计 | 有（需手动） | 弱 | 无（会编造） | 有（自动 + 显著性检验） |
| 语义理解与综合 | 无 | 有 | 有 | 有（仅基于召回材料） |
| 证据可核验 | 手动追溯 | 部分逐句引用 | 无 | 论断级证据核验 |
| 从发现到精读闭环 | 无 | 弱 | 无 | 有（报告→追问→精读） |

本课题的切入点：把「检索透明、计量客观、证据可核验」作为系统约束内置到工作流中，并以对照评测验证其相对「直接问大模型」的优势。

## 三、研究目标与研究内容

### 3.1 总体目标

让学者在不阅读任何具体论文的前提下，通过本系统结合大语言模型直接了解某个研究方向的现状，并核验某个 idea 是否已被实现、实现到什么程度。与「直接在网页上问大模型」的本质区别在于系统做到**客观、系统、可核验**：

| 维度 | 网页问大模型 | 本系统 |
|---|---|---|
| 知识来源 | 模型参数记忆（训练截止冻结） | 实时学术数据库 API（Scopus 机构订阅首选，OpenAlex 兜底回退） |
| 结论性质 | 口头概括，无法核验 | 每条结论挂真实论文证据，可点开原文核验 |
| 「现在大家在做什么」 | 无法回答（会编造） | 统计计算：年份/被引分布、引用率显著性检验、子方向聚类 |
| 过时与幻觉风险 | 高 | 低（数据落盘，模型只做综合不做记忆） |

**系统铁律**：大模型只允许对召回材料做综合与解读，不允许凭记忆回答领域事实问题；没有证据的结论宁可不写，检索为空时明确报告「检索未命中」。

### 3.2 研究内容

系统为前后端分离的单机 Web 应用，包含八个子模块（M7、M8 为已有系统的保留维护项）：

| 模块 | 功能 | 状态 |
|---|---|---|
| M1 统一文献研究工作流 | 自然语言问题（+ 可选工作区母论文）→ 问题拆解为 3–5 条英文学术检索式 → 多源召回 → 富化 → 计量聚类 → 大模型综合 → 结构化调查报告 → 持久化 | 已实现 |
| M2 多源数据融合与额度工程 | Scopus（Elsevier 机构订阅）首选、OpenAlex 熔断回退，辅以 CrossRef / Semantic Scholar / arXiv；批量端点、令牌桶限速、SQLite 元数据缓存、429 指数退避多源回退 | 已实现 |
| M3 客观计量分析 | 相邻完整两年窗口的条件 Poisson 精确检验 + Benjamini-Hochberg 多重检验校正识别引用显著上升；同年被引百分位（样本内前 5%）；期刊 SJR/SNIP；逐年引用轨迹 | 已实现 |
| M4 子方向聚类与关联图谱 | 预训练科学论文向量（标题+摘要）+ mutual-kNN + Leiden 社区划分；工作区线采用八通道对称排名 RRF 关联度、Disparity Filter 骨架标记、关系 PageRank；「年份 × 子方向」热力图、战略坐标四象限、范式卡片 | 已实现 |
| M5 调查报告生成与证据核验 | 参照 RAG Survey 表 II–IV 的结构化报告：技术分类、评估框架、评估维度/指标、下游任务/数据集四类表格 + 覆盖矩阵 + 热力图；每行挂原文摘录证据，程序校验摘录存在于材料中，二轮大模型逐行复核，另有论断级证据核验（借鉴 ALCE） | 已实现 |
| M6 检索增强问答与连续追问 | 领域文献集上的向量检索问答（支持 graph 模式图谱路径证据）；研究面板内连续追问，每轮回答附证据编号与检索上下文，历史回答不作为文献事实证据 | 已实现 |
| M7 单篇精读与代码分析（保留） | PDF 上传解析、AI 结构化精读（贡献/方法/实验/代码映射/QA）、代码仓库 clone 与静态分析、划词翻译总结 | 已实现，维护 |
| M8 评测体系 | 两臂对照评测（系统 vs 同一大模型仅凭记忆）：判定准确率、证据 DOI 可核验率、语料中位年份；调查报告指标（Recall@K、nDCG、引文存在性、证据支持）；离线回归门禁 | 已实现 |

### 3.3 拟解决的关键问题

1. **幻觉与知识过时**：以「LLM 纪律 + 证据挂接」解决——模型输入仅限召回材料，输出结论必须携带可定位的原文摘录；结构化 JSON 输出配失败重试，单点失败降级不阻塞（partial）。
2. **检索质量与多源融合**：问题拆解为多条检索式扩大召回面；多源候选经去重合并后以加权倒数排名融合（RRF）统一排序，再经预训练重排器精排；被引量不作为问题相关性信号，避免马太效应。
3. **「热点」判断的客观性**：以统计显著性检验（条件 Poisson 精确检验 + BH 校正）替代经验倍数阈值规则，显式声明方法假设与不适用情形，区分「样本内上升」与「全领域高被引」。
4. **结论的可核验性**：报告表格逐行强制携带原文摘录，程序校验摘录真实存在于材料中，再由大模型二轮复核行级关系成立性；论断级核验输出支持/矛盾/不足与原文摘录，支持率不完整时置空不夸大。

## 四、技术路线与研究方法

### 4.1 总体架构

前后端分离架构：

- **前端**：React 18 + TypeScript + Tailwind CSS + Vite + Recharts（热力图/统计图）+ Mermaid；SSE 消费研究进度流。
- **后端**：Python + FastAPI + SQLModel + SQLite；后台任务管理器与异步事件总线解耦执行研究流水线，SSE 推送进度。
- **模型接入**：OpenAI 兼容 / Anthropic 兼容 API 统一配置（可对接 DeepSeek 等任意服务商）；嵌入与重排使用可配置的预训练模型（BGE 系列）。
- **外部依赖**：Scopus / OpenAlex / CrossRef / Semantic Scholar / arXiv 公开或机构订阅 API；GROBID（可选，缺失时正则回退）用于参考文献结构化解析。

### 4.2 统一文献研究工作流（主数据流）

```
自然语言问题（+可选母论文）
  → 问题拆解（LLM：检索式 + 意图识别）
  → 多源召回（Scopus 首选 / OpenAlex 熔断回退；后向/前向引文扩展）
  → 元数据富化（期刊指标、逐年被引、摘要关键词）
  → 计量与聚类（引用率检验、被引百分位；embedding + mutual-kNN + Leiden）
  → 综合报告（LLM 仅基于召回材料；结构化表格 + 证据摘录）
  → 证据核验（摘录程序校验 + LLM 行级复核 + 论断级审计）
  → 持久化与呈现（HTML/Markdown 报告、热力图、检索透明度、RAG 追问）
```

### 4.3 关键技术点（论文与答辩核心）

1. **多源检索融合**：问题拆解出的多检索式候选经等权 RRF（k=60）融合统一排序；选材阶段以 BM25+ 与向量两路排名 RRF 融合后再经预训练重排器精排。方法可解释、贡献可分解，被引量不参与问题相关性排序。
2. **互近邻相似图与 Leiden 社区**：以预训练科学论文表示构造 mutual-kNN 图（k=10），Leiden（RBConfiguration）划分子方向社区；Disparity Filter 作为独立统计标记层，不控制主分析图选边——避免少数边通过而多数节点孤立的失真。
3. **引用率变化的显著性检验**：对两个相邻完整两年窗口的被引计数做条件 Poisson 精确检验，集合内 BH 校正控制错误发现率（p≤0.05 且增长方标为显著上升）；显式排除当年不完整数据，逐篇留存检验假设与统计量。
4. **证据优先的综合与核验**：报告行级证据摘录程序校验（Unicode 归一化、跨行断词处理）；ALCE 式论断/引用支持核验；无依据行丢弃并计数，覆盖率透明披露。
5. **检索增强问答**：向量检索 + BM25+ 混合、RRF 融合与重排，支持图谱路径证据叠加；追问场景采用「原始问题 + 近期问题 + 最新问题」联合检索。

### 4.4 实验与评测方案

1. **两臂对照评测（已实现，论文主实验）**：固定 10 道领域问题，A 臂为本系统，B 臂为同一大模型仅凭参数记忆作答。指标：判定准确率（名义类别严格计分）、证据 DOI 可核验率（幻觉暴露面）、语料/引用中位年份（时效性）。已有冒烟结果：对虚构主题，本系统如实报告「检索未命中」，而裸大模型给出确定性判断且零引用。
2. **调查报告质量评测（已实现入口）**：输出检索 Recall@K、nDCG、引文存在性、引文/联合证据支持率；方法参照 SurGE（文献覆盖/引用支持）与 ALCE（论断-引用支持）的指标思想，明确标注「参照思想，不宣称复现官方评测」。
3. **检索消融实验**：纯向量 / 向量+重排 / BM25+向量混合检索的对比（Precision@K、Recall@K、nDCG@K、MRR）。
4. **算法冒烟与回归门禁**：只读真实探索运行做端到端检查（真实配置无降级、聚类/关系/社区产出正常），配合离线 mock 评测基线防回归。

### 4.5 可行性分析（已有工作基础）

本课题为已运行系统的演进与收敛，非从零开发。截至 2026-09-08（版本 v6.1.0）：

- 代码规模：后端 Python 约 4.4 万行（193 个文件，含测试），前端 TypeScript 约 2.5 万行，git 提交 180 次（2026-06-04 至今），开发过程完整可追溯；
- 质量：后端测试 757 项、前端测试 122 项全部通过，Ruff 静态检查、类型编译与生产构建通过；
- 功能：3.2 节 M1–M6 主线功能均已实现并经真实 API 冒烟验证（真实 Scopus/大模型链路完成母论文输入、综合、报告生成、持久化与追问全流程）；
- 数据源：已实测打通 Scopus（Elsevier API Key 绑定机构订阅 IP，校外自动熔断回退 OpenAlex）、OpenAlex、CrossRef、arXiv 检索与下载链路，含出版商直链的合法 OA 定位；
- 成果基础：已申请软件著作权「论文精读辅助分析软件 V1.0」（材料已提交）。

**数据合规**：仅采集公开学术元数据与合法开放获取 PDF（arXiv / Unpaywall 定位的 OA 版本 / 出版商直链的授权下载）；不集成 Google Scholar 爬虫与知网爬虫；遵守各数据源限速条款，客户端令牌桶限速 + 429 指数退避。

**风险与对策**：外部 API 依赖（限速/网络）→ 多源熔断回退与本地缓存；答辩演示 → 离线预置数据 + 录屏兜底；大模型输出不稳定 → 结构化 JSON 重试与 partial 降级。

## 五、预期成果与创新点

### 5.1 预期成果

1. 可运行系统一套：领域文献全景分析与热点发现系统（含统一文献研究、调查报告、证据核验、RAG 追问、单篇精读）；
2. 毕业论文一篇：含两臂对照实验、检索消融实验与真实数据案例分析；
3. 演示材料与可复现的评测脚本（离线可运行）。

### 5.2 特色与创新点

1. **「算法承担客观性、大模型承担可读性」的证据优先架构**：领域现状判断的底层数字全部由统计与图算法产生，大模型仅综合召回材料并被禁止凭记忆回答事实问题——从系统设计层面抑制幻觉与知识过时。
2. **检索透明与论断级证据核验**：检索式与命中数量对用户可见；报告行级强制挂原文摘录并经程序校验 + 模型复核；论断级审计输出支持/矛盾/不足——结论可点开原文核验。
3. **经验规则到成熟算法的严谨化**：热点识别以条件 Poisson 精确检验 + BH 多重校正替代经验倍数阈值；文献关联以对称 RRF + mutual-kNN + Leiden 替代手工调权；方法假设与适用边界显式写入产品与论文。
4. **面向「免读领域全景 + idea 查新」场景的闭环**：问题 → 报告 → 追问 → 精读的连贯工具链，并以系统 vs 裸大模型的两臂对照评测实证差异化价值。
