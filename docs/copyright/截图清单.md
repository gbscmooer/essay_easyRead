# 界面截图清单

> 本文件是**编写用户手册时的准备清单**，不是提交材料的一部分，不要并入《用户手册》。

正式提交前，需按下表核对界面截图。只保留能从当前软件真实界面稳定证明的页面状态；上传中、连接中断等未采集的瞬时状态在正文中用文字说明，不使用无关截图替代。

## 通用要求

- **截图前先运行** `python3 docs/copyright/tools/screenshot_branding.py --apply`，截完用 `--restore` 还原。脚本会一次性处理三件事：把版本号切成 V1.0、隐藏版本弹窗里的 GitHub 仓库链接（含真实账号）、把更新日志换成登记版本的中性描述
- **软件内需有测试数据**，空列表与空图谱看不出功能
- 使用系统截图工具捕获浏览器窗口，**分辨率不低于 1440×900**
- 界面语言为中文，主题不限（现有图均为默认浅色「构成纸面」主题）
- 截图中不得出现真实的接口密钥、个人邮箱、真实公网域名与真实账号，密钥字段保持掩码状态
- 设置页截图前，建议把 API Base URL 临时改成 `https://api.example.com` 这类占位值（改完不要点保存），避免第三方服务商品牌出现在鉴别材料里
- 确认终端面板与顶部标识显示的版本号为 V1.0（软件名已是中文全称，无需检查）
- **文件按编号命名**放入 `docs/copyright/build/screenshots/`，如截图 5-3 存为 `5-3.png`（也接受 `.jpg`）。缺图时生成脚本渲染占位框，可先出稿后补图
- **每个编号必须是一张不同的图**。同一张图挂两个编号会被看作凑数
- 截图插入后，全文每页行数仍需满足不少于 30 行的要求（含图片的页面可豁免）

## 三个容易截废的地方

1. **精读页的 PDF 阅读区**：react-pdf 是异步渲染的，页面刚打开时左栏是空白页。等 PDF 首页真正画出来再截，否则核心功能看上去是空的
2. **深度研究的图谱画布**：力导向布局初始会把节点堆在左上角。先点「开始研究」等布局稳定，再用画布上的缩放控件调到节点铺满视野再截
3. **图题要与画面一致**：图题里写了「最近解析记录」「关联度权重」，画面就得真的滚到那一块；首屏之外的内容不要写进图题
