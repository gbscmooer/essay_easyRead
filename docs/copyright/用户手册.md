本软件面向需要系统性阅读学术文献的研究人员。传统的文献阅读方式依赖读者逐段通读并自行整理笔记，在文献数量较多时效率较低，且难以在多篇论文之间建立稳定的关联认识。本软件把单篇论文的结构化解析与跨论文的图谱分析组织在同一套工具中，使读者既能快速掌握单篇论文的方法与实验要点，也能在一个研究方向的文献集合上观察论文之间的引用与语义关系。

# 第 1 章 软件概述

## 1.1 软件简介

论文精读辅助分析软件是一套面向计算机视觉与机器学习方向研究人员的学术文献精读工具。用户上传 PDF 格式的学术论文后，软件自动完成文本抽取、结构化解析与要点归纳，把一篇非结构化论文转换为可检索、可浏览的结构化阅读材料；解析结果包含定位信息时，还可跳回原文核对。

软件采用前后端分离架构：后端以 Python 语言基于 FastAPI 框架实现，负责文档解析、模型调用、数据持久化与检索计算；前端以 TypeScript 语言基于 React 框架实现，负责界面呈现与交互。两端通过 HTTP 接口与 SSE（Server-Sent Events）事件流通信。持久化数据保存在本地 SQLite 数据库与本地文件系统；模型调用、学术检索和代码仓库克隆可按用户配置访问外部服务。

软件在单篇论文精读之外，进一步提供跨论文的研究能力：用户可将同一研究方向的多篇论文组织为「工作区」，在工作区上运行「深度研究」流程，自动构建论文之间的引文图谱与关联度网络，并基于向量检索完成跨论文的问答。

## 1.2 主要功能

软件的功能划分为七个模块：

**（一）论文解析模块**

接收用户上传的 PDF 文件，抽取正文文本，调用大语言模型完成结构化解析，输出核心贡献、研究问题、论文大纲、方法论、实验设置、代码映射与问答测验七类结构化内容。解析过程在后台异步执行，前端通过事件流实时显示进度。

**（二）论文阅读模块**

提供 PDF 原文渲染视图与解析结果面板的双栏对照阅读界面。支持按章节跳转、页面缩放、专注模式全屏阅读。用户在原文中选中任意文本段落后，可就地发起翻译或摘要生成，也可添加荧光笔、下划线、删除线等标注。

**（三）论文库管理模块**

集中管理已上传的全部论文，提供分页浏览、智能关键词检索、可选的 PDF 全文字面匹配、按领域与年份筛选、多种排序方式、批量删除与批量归入工作区等操作，并支持对全库论文重新提取元数据。这里的搜索是字段和文本匹配，不等同于语义向量检索。

**（四）代码仓库分析模块**

从论文正文中自动识别代码仓库地址，克隆仓库到本地后构建文件树，静态解析各源文件之间的引用依赖关系，并调用模型分析仓库的数据流走向以及论文概念与代码实现之间的对应关系。模块内置代码浏览器与终端面板。

**（五）工作区管理模块**

按研究主题把论文组织为集合。一篇论文可同时属于多个工作区。工作区是深度研究模块的输入单元。

**（六）深度研究模块**

在工作区的论文集合上执行研究流水线：下载缺失的论文全文、解析参考文献、按需联网扩展相关文献、对全文分块并计算向量表示、构建引文图谱、抽取图谱骨架并划分研究子方向。产出的图谱在前端以可交互的力导向图呈现，同时提供跨论文的检索问答功能。

**（七）系统设置模块**

配置解读模型与翻译模型的接入参数、界面主题与字体、深度研究流程的各项参数，并提供模型连通性测试。

## 1.3 技术特点

**结构化解析而非摘要生成。** 软件不是把论文压缩成一段摘要，而是按研究论文的固有结构拆解为方法流程、关键模块、数据集、基线方法、实验结果表格等字段；在解析结果提供定位信息时，用户可回到原文对应位置核对。

**解析过程与页面浏览解耦。** 论文解析在后端以后台任务方式运行，前端仅作为事件订阅方。用户关闭页面或切换路由不会中断解析；重新进入页面时会回放已缓冲的进度事件并继续接收后续进度，无需重新发起解析。

**统一的论文关联度度量。** 深度研究模块中论文之间的关系强度由单一算法给出：从主题向量、研究目的、方法、术语重叠、共享数据集、共享基线、文献耦合、共引八个通道分别计算相似度，各通道经分位数归一化后加权融合为一个分数。该分数同时决定图谱的连边、社区划分、节点重要性与检索排序。

**通道权重的自监督校准。** 各通道的判别力随语料而变。软件在建图时以工作区自身的引用结构（直接引用关系与文献耦合关系）作为弱标签，度量每个语义通道的实际判别力，据此重新分配权重，并按证据量向先验权重收缩。证据不足或判别力与随机无异的通道保持先验值不变。

**基于目标密度的图谱控制。** 图谱骨架的密度旋钮是「目标平均度」，即每篇论文平均连出的边数。软件二分求解关联度阈值以逼近该目标，再执行显著性检验保留局部显著的边。密度控制与打分尺度无关。

**本地优先的数据存放。** 论文原文、解析结果、标注笔记、向量索引与图谱数据保存在本地。论文解析、文本操作、学术检索、联网扩展与代码仓库克隆等功能会按用户配置访问外部服务。

## 1.4 适用对象

本软件面向需要系统性阅读学术文献的人员，包括高等院校计算机及相关专业的研究生、科研院所研究人员、企业研发人员。使用者应具备基本的计算机操作能力，了解命令行的基本使用方法。

## 1.5 术语说明

| 术语 | 说明 |
|------|------|
| 精读 | 对单篇论文执行完整的结构化解析，产出全部七类结构化内容 |
| 速读 | 轻量级解析，仅抽取研究目的、方法、数据集、基线与简短总结，供图谱建立关系使用 |
| 工作区 | 按研究主题组织的论文集合，是深度研究的输入单元 |
| 深度研究 | 在工作区上运行的跨论文分析流程，产出引文图谱与向量索引 |
| 引文图谱 | 以论文为节点、以论文间关系为边的网络结构 |
| 论文关联度 | 衡量两篇论文相关程度的综合分数，由八个通道加权融合得出 |
| 骨架提取 | 从全连接的关联度矩阵中筛选出显著边，得到稀疏可读图谱的过程 |
| 目标平均度 | 图谱密度的控制参数，表示每篇论文平均连接的边数 |
| 子方向 | 图谱社区划分的结果，表示工作区内部的研究分支 |
| RAG 问答 | 检索增强生成，先检索相关文本片段再据此生成回答的问答方式 |
| 扩展论文 | 深度研究联网抓取到的、原本不在论文库中的相关文献 |
| SSE | Server-Sent Events，服务器向浏览器单向推送事件的通信机制 |
| GROBID | 用于解析学术文献结构与参考文献的开源工具 |

## 2.3 网络要求

软件本身在本地运行，界面访问不依赖外部网络。以下功能需要网络连接：

- 论文结构化解析、文本翻译、摘要生成：需访问用户配置的大语言模型服务地址
- 相关论文推荐：需访问学术文献检索服务
- 深度研究的联网扩展阶段：需访问文献元数据服务与论文托管站点
- 代码仓库分析：需访问代码托管平台以克隆仓库

在深度研究页面将构建范围选择为「仅本地」时，联网扩展阶段被跳过，图谱仅基于工作区已有论文构建。

# 第 3 章 安装与部署

## 3.1 获取程序

将软件的完整源程序目录复制到本机任意路径。以下操作均以该目录为当前工作目录，文中记为「项目根目录」。

## 3.2 配置环境变量

复制项目根目录下的环境变量样例文件，并填入模型服务的接入参数：

```
cp .env.example .env
```

用文本编辑器打开 `.env` 文件。没有模型密钥时，软件仍可启动并浏览本地论文库；需要解析、翻译或总结时再填写模型参数：

```
LLM_API_KEY=用户申请的接口密钥
LLM_BASE_URL=模型服务地址
LLM_MODEL=模型名称
```

参数说明：

| 变量名 | 是否必填 | 说明 |
|--------|----------|------|
| `LLM_API_KEY` | 可空 | 模型服务的接口密钥；调用模型的功能需要填写 |
| `LLM_BASE_URL` | 选填 | 模型服务地址。地址中包含 `anthropic` 时按 Anthropic 消息协议调用，否则按 OpenAI 对话补全协议调用 |
| `LLM_MODEL` | 选填 | 模型名称 |
| `DATABASE_URL` | 选填 | 数据库文件路径，默认 `sqlite:///./data/essay_read.db` |
| `UPLOAD_DIR` | 选填 | 上传文件存放目录，默认 `./uploads` |
| `HOST` | 选填 | 后端监听地址，默认 `127.0.0.1` |
| `PORT` | 选填 | 后端监听端口，默认 `8000` |
| `FRONTEND_ORIGIN` | 选填 | 前端访问地址，用于跨域许可，默认 `http://localhost:5173` |

「设置」页面只保存翻译模型、解读模型、提示词、界面和深度研究配置；数据库、上传目录、监听地址和端口仍由环境变量或启动脚本控制。设置页保存的模型类配置写入 `data/ai_config.json` 文件。

## 3.3 安装后端依赖

在项目根目录创建并激活 Python 虚拟环境，随后安装后端依赖：

```
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
cd backend
pip install -r requirements.txt
cd ..
```

Windows 系统下激活虚拟环境的命令为 `.venv\Scripts\activate`。

## 3.4 安装前端依赖

```
cd frontend
npm install
```

## 3.5 一键启动

项目根目录提供启动脚本，依次完成端口检查、后端启动、前端启动、健康检查，并默认启动 GROBID 引用解析服务：

```
./start.sh
```

脚本默认使用 8000 端口运行后端、5173 端口运行前端。端口已被占用时，脚本会提示并跳过对应服务，其他服务继续尝试启动。默认的 GROBID 启动需要 Docker；Docker 未运行时脚本会尝试唤起 Docker Desktop，无法使用时引用解析会回退为正则解析。只需基础功能时可使用 `./start.sh --no-grobid` 跳过该服务。

浏览器访问 `http://localhost:5173`。页面正常显示首页，且首页统计区能够读出论文数量与工作区数量，即表示前后端连通、数据库初始化成功。

后端接口文档位于 `http://localhost:8000/docs`，可用于确认后端服务状态。

首页是软件的入口，路径为 `/`。页面自上而下分为四个区域。

**标题与投放区。** 页面上半部分为标题区，下方横贯整条底边的区域为文件投放区。投放区支持拖拽投放与点击选择两种方式，仅接受 PDF 格式文件。上传过程中显示进度百分比；上传失败时在投放区下方显示错误提示。

**统计区。** 显示四项计数：论文库中已上传的论文总数、工作区数量及其收录论文总数、深度研究联网扩展发现的论文数量、近期条目数量。

**最近解析。** 列出最近上传的六篇论文，每行显示序号、论文标题、发表会议与年份、解析状态。状态取值包括「已完成」「已索引 · 待解析」「尚未解析」「失败」与「处理中」。点击任意一行进入该论文的精读页面。点击区块右上角的「查看全部」进入论文库。

**快捷入口与最近工作区。** 页面右侧提供论文库、工作区、深度研究三个快捷入口；点击「深度研究」会先进入工作区列表，选择工作区后再进入对应研究页面。下方列出最近更新的四个工作区，显示各自的论文数量与更新日期。

## 5.2 上传论文

**操作步骤：**

1. 在首页找到底部的投放区
2. 从文件管理器中拖拽 PDF 文件到投放区，或点击投放区后在弹出的对话框中选择文件
3. 松开鼠标或确认选择后开始上传，投放区显示进度
4. 上传成功后自动跳转至精读页面并开始解析

**约束条件：**

- 仅接受 PDF 格式
- 论文正文文本超过 10 万字符时，软件优先保留前 3 页和最后 1 页，并继续按顺序纳入容量允许的中间页面，以控制单次模型调用的输入规模
- 上传的文件以随机标识符命名后存放于 `uploads` 目录，原文件名记录在数据库中

**异常处理：** 上传失败时投放区下方显示「上传失败，请检查文件格式后重试」，同时右上角弹出提示。此时确认文件确为 PDF 格式且未损坏后重新上传。

# 第 12 章 常见问题与故障排除

## 12.1 启动阶段

**问：执行 `./start.sh` 提示端口已被占用。**

答：软件默认使用 8000 端口运行后端、5173 端口运行前端。可执行 `lsof -i :8000` 或 `lsof -i :5173` 查找占用进程并停止后再启动。当前启动脚本、前端代理与健康检查均按 8000 端口连接后端；若必须更换后端端口，需要同步修改启动参数和前端代理配置，不能只修改 `.env` 中的 `PORT`。

**问：前端页面能打开，但所有数据都加载失败。**

答：说明后端未正常启动或跨域许可未通过。先访问 `http://localhost:8000/docs` 确认后端在运行，再检查 `.env` 中的 `FRONTEND_ORIGIN` 是否与实际访问地址一致。

## 12.2 解析阶段

**问：上传成功但解析一直没有进度。**

答：依次检查三项：设置页面的解读模型是否已填写接口密钥；「测试连接」是否通过；本机能否访问所配置的模型服务地址。

**问：解析中途提示连接中断。**

答：这是前端与后端的事件流连接断开，后台解析任务仍在运行。点击「重新连接」即可继续接收进度，不要点击「重新分析」，否则会重新消耗计算额度。

**问：解析结果中部分字段为空。**

答：软件对论文正文超过 10 万字符的情况会做截断处理，优先保留前 3 页和最后 1 页，并继续按顺序纳入容量允许的中间页面。若论文篇幅过长或版式特殊导致文本抽取不完整，仍可能出现部分字段为空。可尝试点击「重新分析」。

## 12.3 划词与代码分析

**问：选中文本后没有弹出操作气泡。**

答：确认选中的是 PDF 文本层的内容。扫描版 PDF 没有文本层，无法选中文字。

**问：点击翻译提示需要配置。**

答：翻译功能使用「翻译模型」而非「解读模型」，需在设置页面单独填写翻译模型的接口密钥。可与解读模型使用同一套参数。

**问：克隆仓库失败，或代码选项卡显示未找到源码地址。**

答：软件通过匹配论文正文中的代码托管平台链接来识别仓库，论文未提供链接时无法识别，可点击「重新查找」再次尝试。克隆失败时确认本机能访问该代码托管平台，且仓库地址正确、仓库为公开状态。

## 12.4 深度研究

**问：点击开始研究后提示工作区没有可用于深度研究的论文。**

答：至少需要一篇状态为「已完成」「已索引 · 待解析」或「待解析」的工作区论文。单篇论文也可启动研究，但不会形成论文之间的关系边。

**问：图谱边太多或太少。**

答：图谱密度由「目标平均度」控制，表示每篇论文平均连接的边数。在研究设置中调整该参数后重新运行研究。

**问：不希望联网抓取文献。**

答：在深度研究页面把构建范围选择为「仅本地」，这样本次运行会跳过联网扩展，图谱仅基于工作区已有论文构建。

## 12.5 数据管理

**问：论文文件存放在哪里。**

答：上传的 PDF 存放于项目根目录的 `uploads` 目录，以随机标识符命名。克隆的代码仓库存放于 `code_downloads` 目录，按论文标识分子目录。数据库文件位于 `data` 目录。

**问：删除论文后数据是否可恢复；如何备份。**

答：删除后不可恢复，批量删除前会弹出确认对话框提示。备份 `data`、`uploads` 与 `code_downloads` 三个目录可保留服务端全部持久化数据；阅读位置、面板布局等偏好保存在浏览器中，不包含在这三个目录内。
