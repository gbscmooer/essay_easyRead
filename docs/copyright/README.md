# 软件著作权申请材料

本目录存放本项目申请计算机软件著作权登记所需的全部材料与生成工具。

## 结论

**本项目可以申请软件著作权。** 有效代码 38,491 行，远超 3000 行门槛；功能完整、可独立运行；个人独立开发、业余时间完成、从未公开传播，权利关系清晰，可按「未发表」登记，无需公开源代码。

全程个人可独立完成，0 费用，发放电子证书。

## 目录内容

| 文件 | 用途 |
|------|------|
| `申请指南.md` | 资格结论、权利情况、材料要求、六步申请流程、风险提示、提交前自查清单 |
| `申请表填写指引.md` | 申请表逐字段取值，全部已实测字数；含办理路径速查与常见补正原因 |
| `用户手册.md` | 文档鉴别材料正文，12 章 + 2 附录 |
| `截图清单.md` | 37 项界面截图的准备清单（编写用，不提交） |

| `tools/gen_manual_docx.py` | 把用户手册转成带封面、目录、页眉页码的 .docx |
| `tools/screenshot_branding.py` | 截图前临时切换界面品牌与版本号到登记口径 |

| `build/` | 脚本输出目录（不纳入版本控制） |

## 操作顺序

### 1. 先去实名认证

访问 `https://www.ccopyright.com.cn` 注册并完成个人实名认证。**审核要 1–3 天，这一步最先做**，其余工作并行进行。

### 2. 生成程序鉴别材料

```bash
python3 docs/copyright/tools/gen_source_doc.py \
    --name "论文精读辅助分析软件" --version "V1.0"
```

输出 `build/源程序.docx`：A4，60 页（前 30 + 后 30），每页 50 行，无封面首页即代码，页眉含软件全称与版本号，右上角自动页码。

用 Word 打开，确认页数与末页闭合后，导出为 PDF。

### 3. 生成用户手册

```bash
python3 docs/copyright/tools/gen_manual_docx.py \
    --name "论文精读辅助分析软件" --version "V1.0" \
    --owner "你的姓名"
```

输出 `build/用户手册.docx`：自动生成封面与目录，`【截图 x-x】` 渲染为带边框的占位框和图题。

### 4. 准备测试数据并截图

```bash
# 切换界面品牌与版本号到登记口径
python3 docs/copyright/tools/screenshot_branding.py --apply

./start.sh
# 上传两三篇论文、跑一次解析、建工作区、跑一次深度研究，让界面有内容
# 按 截图清单.md 的 37 项清单逐一截图

python3 docs/copyright/tools/screenshot_branding.py --restore
```

### 5. 通读改写用户手册

**这一步不能省。** 详见下方「两个必须人工处理的点」。

### 6. 在线填报并提交

按 `申请表填写指引.md` 逐字段填写，上传两份 PDF，签署申请表。流程速查见该文件第十节。

## 两个必须人工处理的点

### 文档鉴别材料的 AIGC 审查

登记机构对 AIGC 内容的审查已趋严，**已有申请人因文档鉴别材料被判定为 AI 生成而被要求补正**。代码用 AI 写未见因此被拒的报告，风险集中在文档。

`用户手册.md` 由 AI 撰写，内容基于对本项目前端代码的逐页核对，写的是界面上真实存在的按钮与文案，不是通用模板；但行文特征仍可能被识别。

**把它当作内容清单和结构骨架用**——它保证不漏功能点、章节层次符合登记要求——文字请你自己过一遍。有效做法：先截图，再对着每张图用自己的话重写对应章节。详见《申请指南》6.1 节。

### 界面旧项目名与版本号冲突

登记要求截图中的名称与版本号必须与申请表一致。本项目界面上有四处冲突，且出现在几乎每张截图里：

| 位置 | 当前显示 |
|------|----------|
| 顶部品牌区（每页都有） | `ER` / `EASY ESSAY` / `RESEARCH INTELLIGENCE` |
| 浏览器标签页 | `Easy Essay` |
| 终端面板 | `v5.2.0` |
| 版本弹窗 | `V5.2.0` / `Easy Essay` |

`screenshot_branding.py` 在截图期间临时切换这四处，截完还原。它只替换字符串字面量，不进入主线代码，也不改动项目的版本管理逻辑。脚本会先检查目标文件有无未提交改动，有则拒绝执行。

> 本环境未安装前端依赖，无法完整验证切换后的编译结果。补丁只替换 JSX 文本与字符串常量，语法上安全，但建议截图前先跑一次 `npm run build`。

## 工具说明

生成脚本零依赖，只用 Python 标准库，`docx_writer.py` 直接构造 OOXML 包，不需要安装 python-docx 或 Word。

登记要求中最容易翻车的是「每页不少于 50 行」——交给 Word 自动断页的话，行数会随字体、行距和渲染环境浮动。脚本的做法是按显示列宽硬折行、设定精确行距、逐页硬分页，把页面行数变成确定的排版结果。

常用参数：

```bash
# 查看源程序统计（申请表「源程序量」填这个数）
python3 docs/copyright/tools/gen_source_doc.py --stats

# 代码不足 3000 行时提交全部源程序
python3 docs/copyright/tools/gen_source_doc.py --full

# 更严格的口径，剔除全部纯注释行
python3 docs/copyright/tools/gen_source_doc.py --stats --strip-comments

# 调整每页行数与折行宽度
python3 docs/copyright/tools/gen_source_doc.py --lines-per-page 55 --wrap-width 90
```
