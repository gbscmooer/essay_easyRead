# 软件著作权申请材料

本目录存放本项目申请计算机软件著作权登记所需的全部材料与生成工具。

## 结论

**本项目可以申请软件著作权。** 有效代码 38,491 行，远超 3000 行门槛；功能完整、可独立运行；代码仓库为私有，可按「未发表」登记，无需公开源代码。

唯一的实质性人工工作是**补 37 处界面截图**，其余材料均可由本目录的脚本自动生成。

## 目录内容

| 文件 | 用途 |
|------|------|
| `申请指南.md` | 资格结论、材料清单、申请流程、名称与版本号规范、风险提示、自查清单 |
| `申请表填写指引.md` | 申请表逐字段的建议取值，含功能与技术特点的可直接采用稿 |
| `用户手册.md` | 文档鉴别材料正文，12 章 + 3 附录 |
| `tools/gen_source_doc.py` | 生成 60 页源程序鉴别材料 |
| `tools/gen_manual_docx.py` | 把用户手册转成带封面、目录、页眉页码的 .docx |
| `tools/docx_writer.py` | 零依赖的 OOXML 生成内核，被上面两个脚本共用 |
| `build/` | 脚本输出目录（不纳入版本控制） |

## 快速开始

### 1. 查看源程序统计

申请表要填「源程序量」，用这个命令取值：

```bash
python3 docs/copyright/tools/gen_source_doc.py --stats
```

### 2. 生成源程序文档

```bash
python3 docs/copyright/tools/gen_source_doc.py \
    --name "论文精读辅助分析软件" \
    --version "V1.0"
```

输出 `build/源程序.docx`：A4，60 页（前 30 页 + 后 30 页），每页 50 行，页眉含软件名称与版本号，右上角自动页码。

### 3. 生成用户手册文档

```bash
python3 docs/copyright/tools/gen_manual_docx.py \
    --name "论文精读辅助分析软件" \
    --version "V1.0" \
    --owner "著作权人姓名或单位全称"
```

输出 `build/用户手册.docx`：自动生成封面与目录，`【截图 x-x】` 渲染为带边框的占位框和图题。

### 4. 补截图

用 Word 打开 `build/用户手册.docx`，把界面截图逐一粘贴进占位框内。清单见 `用户手册.md` 附录 C。

### 5. 核对后提交

按 `申请指南.md` 第八节的自查清单逐项确认，然后到中国版权保护中心官网填报。

## 需要你先确认的三件事

脚本无法替你决定，且会影响材料内容：

1. **著作权人**——个人姓名还是单位全称
2. **是否构成职务作品**——在校或在职期间开发可能归属单位
3. **发表状态**——若曾提供他人使用或部署过对外服务，则不能填「未发表」

详见 `申请指南.md` 第五节。

## 工具说明

两个生成脚本零依赖，只用 Python 标准库，`docx_writer.py` 直接构造 OOXML 包，不需要安装 python-docx 或 Word。

登记要求中最容易翻车的是「每页不少于 50 行」——若交给 Word 自动断页，行数会随字体、行距和渲染环境浮动。脚本的做法是按显示列宽硬折行、设定精确行距、逐页硬分页，把页面行数变成确定的排版结果。

常用参数：

```bash
# 代码不足 3000 行时提交全部源程序
python3 docs/copyright/tools/gen_source_doc.py --full

# 采用更严格的口径，剔除全部纯注释行
python3 docs/copyright/tools/gen_source_doc.py --stats --strip-comments

# 调整每页行数与折行宽度
python3 docs/copyright/tools/gen_source_doc.py --lines-per-page 55 --wrap-width 90
```
