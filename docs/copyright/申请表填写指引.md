## 八、鉴别材料上传

**两份材料最终都要提交 PDF，不是 Word。** 用脚本生成 docx 后，在 Word 中「文件 → 导出 → 创建 PDF/XPS 文档」导出为文本型 PDF（不要用截图拼成的图片型 PDF）。

| 材料 | 生成命令 | 后续处理 |
|------|----------|----------|
| 程序鉴别材料 | `python3 docs/copyright/tools/gen_source_doc.py` | 核对 60 页与末页闭合，导出 PDF |
| 文档鉴别材料 | `python3 docs/copyright/tools/gen_manual_docx.py --owner "你的姓名"` | 补 37 处截图，通读改写，导出 PDF |

上传时交存方式选「**一般交存**」。「其他证明材料」为空，跳过即可——独立开发不涉及委托或合作开发协议。

## 九、申请表签署（最后一步）

在线填报提交后，系统会生成一份申请表供下载。个人申请只需填右下角：**本人签名 + 身份证号**，不需要公章。

⚠️ **新版申请表可能包含需手抄的承诺条款**，内容涉及「未使用 AI」与征信承诺。据社区反馈，该条款曾出现又被撤下，各批次表单不一致。

**请以你自己下载到的那份申请表为准。** 如果表上确实有该条款，是否签署、如何签署由你本人判断——这是需要你签名承担责任的法律文件，不应由他人代为决定。相关背景见《申请指南》第六节。

## 十、办理路径速查

1. 官网 `https://www.ccopyright.com.cn` 注册并完成个人实名认证（**审核需 1–3 天，最先做**）
2. 业务办理 → 选「**R11 计算机软件著作权登记**」
3. 身份选择 → 选「**我是申请人**」（个人申请，验证码发到本人手机）
4. 填写软件基本信息 → 发表状态选「**未发表**」
5. 上传程序鉴别材料与文档鉴别材料 → 交存方式选「**一般交存**」
6. 填写十余项文字内容（即本文第二至六节，可直接复制粘贴）
7. 确认信息 → 提交 → 接收手机验证码授权（**验证码 1 小时有效，期间不要刷新页面或断网**）
8. 下载申请表 → 签名 + 身份证号 → 扫描上传
9. 定期登录查看进度；如遇补正，按要求修改后重新上传

个人申请全程 0 费用，证书为电子证书，不涉及邮寄。

## 十一、常见补正原因

以下均为形式问题，事前核对即可避免：

| 补正原因 | 预防措施 |
|----------|----------|
| 文档鉴别材料被判定为 AI 生成 | 通读改写用户手册，见《申请指南》第六节——**这是当前最高频的补正原因** |
| 软件名称在申请表与鉴别材料中不一致 | 名称只从一处取值，用脚本 `--name` 参数统一注入 |
| 截图中出现冲突版本号 | 截图前运行 `tools/screenshot_branding.py --apply`（软件名已在主线代码中统一，无需处理） |
| 字数超限或不足 | 「主要功能」必须 500–1300 字符，「技术特点」≤100 字符，其余环境字段 ≤50 字符 |
| 源程序每页不足 50 行 | 脚本按固定 50 行/页硬分页，不依赖 Word 自动断页 |
| 源程序末页停在未闭合语句 | 脚本已让末页收尾于组件的自然结束处，导出前再目视确认一次 |
| 源程序混入配置文件、依赖、第三方协议正文 | 脚本只采集 `.py`/`.ts`/`.tsx`/`.js`/`.jsx`，已排除测试与依赖目录 |
| 提交了 Word 而非 PDF | 两份鉴别材料都需导出为文本型 PDF |
| 文档鉴别材料缺少界面截图 | 有操作界面的软件必须含操作步骤截图，见 `截图清单.md` |
| 截图含真实密钥或个人信息 | 使用测试数据，密钥字段保持掩码状态 |
